# AGENTS.md

Guidance for coding agents working in this repository. User-facing documentation lives in [README.md](README.md).

## Project overview

Simulacra (formerly Abstract Art) is a generative art program that draws abstract patterns and stylized representations of real phenomena: 48 styles, 24 palettes, PNG, APNG and GIF output, and a command line. It is a Rust-only project: `core/` is a Cargo workspace with `engine` (package `simulacra_engine`: scenes, shaders, palettes, noise; usable as a library) and `cli` (package `simulacra_cli`, the `simulacra` binary with its PNG, APNG and GIF writers). It was ported pixel for pixel from a Python reference, `simulacra.py`, which was retired in the Python cutover (PLAN.md Phase 6; design in `docs/superpowers/specs/2026-11-11-python-cutover-design.md`); read it in git history before that change if a porting comment needs it. Committed golden hashes and portable fixtures recorded while the Python comparison still passed now pin every style's output. No styles are being added or changed for now. Third-party dependencies are allowed.

```bash

cargo test $M && cargo clippy $M --all-targets -- -D warnings                      # whole workspace, platform libm
cargo test $M --features portable && cargo clippy $M --all-targets --features portable -- -D warnings   # CI checks both backends
cargo test $M -p simulacra_engine && cargo clippy $M -p simulacra_engine --all-targets --features portable -- -D warnings   # the engine on its own
cargo test $M -p simulacra_engine --features json,portable   # portable fixtures: committed scenes must render their recorded SHA-256
```

## CI

- **Tests (`.github/workflows/tests.yml`):** runs on every push to main and every pull request, forks included (no secrets): `cargo test` plus Clippy with `-D warnings` on both backends, for the workspace and then for the engine alone, plus the portable fixtures (`--features json,portable`, and `json` alone, where they only have to load and render); and a `golden` job: `golden_selftest.sh`, then `golden.sh check --keep` against a portable release binary and the `golden_pixels` test on that directory.
- **SonarQube Cloud (`.github/workflows/sonarqube.yml`, `sonar-project.properties`):** runs `core/coverage.sh` (cargo-llvm-cov 0.9.1, installed by `taiki-e/install-action`, with `llvm-tools-preview`) in one step, since it sources `cargo llvm-cov show-env` into its own shell (its output is shell-quoted, so it must not be copied into `$GITHUB_ENV`). It runs the workspace tests and the engine with `json,portable` in the dev profile (`cargo llvm-cov report` reads one profile directory; the CLI integration tests run the instrumented binary Cargo builds for them), writes `lcov.info` and runs `core/check_lcov.sh`, which fails on a malformed `DA` line, on no hits for the line `let args = Args::parse();` in `main()` of `core/cli/src/main.rs` (only the binary runs it), or on no hits under `core/engine/src/styles`, so a collection that silently stopped contributing cannot just lower the figure. New code is held to the quality gate's 80% coverage. `sonar.sources` lists the crates' `src` directories (add a new crate there), and the palette table `core/engine/src/palettes.rs` is excluded from duplicate detection (`sonar.cpd.exclusions`), since its rows of tuples made the duplication gate fail. The scan needs `SONAR_TOKEN` and skips pull requests from forks, which cannot read secrets. SonarQube's Automatic Analysis must be off, because it conflicts with CI analysis.
- **Release binaries (`.github/workflows/release-binaries.yml`):** test builds with `cargo install --locked --path core/cli --features portable` (the README's install command, from a checkout) for `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu` and `x86_64-pc-windows-msvc` (macOS is not a target), each on a native runner that also runs the portable fixtures and the CLI tests, on pushes to main and pull requests that touch `core/` or the workflow, and by hand. A `verify` job downloads each package (tar.gz, or zip on Windows) on a fresh runner and runs `golden.sh check` on it: every golden workload must hash as committed, so every target renders the same images, and on Linux the binary runs in a pinned `debian:trixie-slim` image without Python or Rust. Nothing is published; the packages are artifacts kept 14 days.
- **OSV-Scanner (`.github/workflows/osv-scanner.yml`):** scans `-r ./`, which finds `core/Cargo.lock`. Pull requests and merge groups use the PR workflow, and pushes to main, a weekly schedule and manual runs use the full scan. Results are uploaded to GitHub code scanning, except for pull requests from forks, whose tokens cannot write security events, and for merge groups, whose scan compares the commit with itself (the PR workflow reads `GITHUB_BASE_REF`, which GitHub sets only for pull requests). Actions are pinned by commit SHA with the version in a comment.

## Architecture

- **Registry:** the engine's `for_each_style!` macro in `core/engine/src/lib.rs` is the one list of styles: it generates `STYLES` and the scene deserialization. `scene_builders!` in `core/engine/src/scenes.rs` lists each style's scene struct and generates `SCENE_BUILDERS` (alphabetical; the binary's `--style` choices and `--list-styles`), `build_scene` and `build_scene_json`. A style needs one line in each.
- **Scenes and shaders:** a scene struct implements `BuildScene::build(&SceneParams)` (width, height, the full 64-bit seed, the palette, the phase), which makes all of the style's random draws, and `Style::render(width, height, seed32, palette)`, which shades rows in parallel (rayon) and returns packed RGB bytes. Shaders take the 32-bit `seed32(seed)` (`seed as u32`). Shared helpers `circle_offset`, `golden_start` and `ROUGH_TAU` (Python's `6.28`) live in `styles/mod.rs`, with `gaussian`, `unit`, `center` and `small_side`; `geometry.rs` holds `py_mod`, `py_sum`, and polygon and segment distances.
- **Randomness:** `simulacra_engine::PyRandom` (`core/engine/src/random.rs`) reproduces CPython's `random.Random` for `i64` seeds draw for draw (MT19937 seeding, `random`, `uniform`, `randint`, single-argument `randrange`, `choice`, `getrandbits` up to 128 bits), so every seed keeps the scene it had in Python. `core/engine/tests/random_reference.json` holds CPython sequences, written before the cutover, that `tests/py_random.rs` replays. Use only those methods; a new one must reproduce the same draws as the reference did (derive per-item values from the index instead where possible).
- **Python semantics in the code:** the shaders and builders reproduce the retired Python reference operation for operation, and the golden hashes depend on it: no algebraic rewrites, no `mul_add` outside the error-free products in `py_hypot`, no `clamp` where `max`/`min` NaN behavior differs, `x ** n` with a float base as `m_powf` (not `powi`), `round()` as `round_ties_even`, `int()` as a truncating cast, float `%` as `geometry::py_mod`, compensated `sum()` as `geometry::py_sum`, and `(distance, value)` tuple ordering where ties matter (see `Voronoi`). Comments naming Python functions (`_mosaic_scene`, `render_waves`) refer to that reference.
- **Libm:** call transcendental functions through the `Libm` trait in `core/engine/src/math.rs` (`x.m_exp()`, `m_sin`, `m_cos`, `m_tan`, `m_tanh`, `m_atan`, `m_atan2`, `m_powf`, `m_ln_1p`), never the `f64` methods (`core/clippy.toml` forbids them outside `math.rs`). The default build uses the platform libm; the `portable` feature swaps in the pure-Rust `libm` crate so every platform gives the same image, and release builds, the fixtures and the golden hashes use it. `math::py_hypot(x, y)` is an exact port of CPython's `hypot`, shared by both backends; `f64::hypot` is forbidden as well. On the platform libm, `attractor` and `cymatics` differ from the portable images (PLAN.md, "Measured `portable` drift"); PR 3 of the cutover decides whether that backend stays.
- **Noise:** `fbm()` returns values in `[0, 1]` centered near 0.5. Do not treat it as `[-1, 1]` (`n * 0.5 + 0.5` was a past bug in 8 styles). Use `contrast(n, gain)` to stretch it, and `polar_noise()` for anything indexed by an angle, because raw `theta` creates a seam at ±π. `fbm()` uses the same seed for every octave, so octaves are correlated at the lattice points; changing that would alter every noise-based style.
- **Looping noise:** `fbm_loop` blends a stack of ordinary 2D noise layers, each the same noise under the seed plus `7919 * layer`. Layer 0 is the real seed, so phase 0 is exactly the still noise, and the layer index wraps, so phase 1 repeats phase 0. Octave `i` steps through `NOISE_LAYERS + i` layers per loop so the octaves do not all stall or pulse together. The blend is linear on purpose; an eased blend varied the speed about 3x and hitched at the loop point. A style animates its noise by putting the phase in its scene for the shader; a looping-noise phase is validated by `check_loop_phase` (finite only) since huge phases are reduced by the noise.
- **Animation:** every style moves. A builder adds `loop_angle(phase, k)` (`tau * k * (phase % 1.0)`, `k` a whole number, negative to reverse) to phases and angles, or circles positions with `circle_offset()` (exactly zero at phase 0), without new random draws, so phase 0 is the still image and phase 1 repeats it. Offsets that are not whole turns (the drift in `voronoi`) are measured from their starting value so phase 0 adds exactly 0.0. Brush and trail styles move their scene data (comet, ember, flowfield starts, ink control points, constellation stars via `drift_stars`; constellation pairs are chosen from the starting positions so the line set stays constant), and `lissajous` turns its curve phases. `torus` rotates its model points (an exact identity at angle 0) and takes the depth range from the turned knot but the centre and scale from the unturned one; `quasar` adds a loop to the jet's spin; `mandala` counter-rotates ring and spoke phases; per-ring turbulence in `quasar` and `mandala` stays fixed. `mandelbrot` gets `scale`, `center` and `iterations` from its scene: the zoom is `exp(-depth * ease)` with a cosine ease, the centre moves with `1 - closing`, and phase 0 is exactly the original view; it ignores the seed. Shards turn with `turned_about`, which adds the offset to the point. The binary's frame phases are `frame_plan` in `core/cli/src/main.rs`: `py_mod(phase, 1.0) + i / frames`, or consecutive seeds with `--slideshow`.
- **Brush and trail styles** (torus, lissajous, constellations, ink, flowfield, comet, ember, attractor; `core/engine/src/styles/brush.rs`) stamp sequentially in a fixed order into a shared buffer and then shade in parallel, since float addition order changes results. `sample_by_length` samples the torus and lissajous curves at a spacing tied to the glow width. Parallelizing the stamping (one band of rows per thread, each replaying all stamps in order) is possible if `ink` at very large sizes matters.
- **Attractor:** parameters come from `ATTRACTOR_TABLE` in `brush.rs` (256 sets, mirrored on one random bit), chosen with integer draws only, so no libm changes a seed's figure. Entries were checked offline at 384 phases for a lively figure that stays the same from four nearby start points under both glibc and the `libm` crate (PLAN.md, "Attractor parameter table"); add entries only with the same checks. It counts integer hits, so order does not matter, but its orbit is chaotic, which is why its image depends on the libm.
- **Marbling** undoes its ops (drops and combs, each exactly invertible) from last to first per pixel, so scene order is the order they were applied; drops circle and comb strength is scaled by `cos(loop_angle(...))`.
- **Space styles** (`space.rs`): distances use `sqrt(dx * dx + dy * dy)` rather than `hypot`. `lunar` marches a soft shadow through its analytic crater height field; `asteroids` shades rocks nearest first and takes the first hit; `blackhole` maps the sky through `1 - 1.6 / r**2` to fake lensing; `supernova` evolves its filaments with looping noise.
- **Woodblock** samples animated hill, cliff and wave silhouettes per column in canvas-relative units and shades overlapping layers and carved contour grooves; the final palette stop is paper. `watercolor` is a palette, not a filter.
- **Mosaic** computes one palette position per tile on a grid about `MOSAIC_TILES` tiles across the short side, so the work does not grow with the canvas, and the shader only expands tiles and grout to pixels. Its noise is sampled in tile units (`value_noise` has an 8-unit cell, so scales near 1). Patterns move by whole tiles, wrapping after one period per loop.
- **Scene validation (`core/engine/src/validate.rs`):** every `Style` implements `validate(&Canvas) -> Result<f64, SceneError>`, which checks the scene and returns its estimated work; the checked `simulacra_engine::render` calls `validate_scene` before shading, and the binary renders through it (`Style::render` itself is unchecked). Every float field goes through `check_numbers!` (finite, at most 2**40), except a looping-noise phase (`check_loop_phase`); indices and lengths are checked against the canvas, the palette and each other; a style that allocates a canvas-sized buffer per item caps the count (`lissajous` 8 curves, `horizon` 64 layers); and the work estimate counts inner-loop iterations per pixel, with sequential steps weighted by `SEQUENTIAL_WEIGHT` and attractor steps by `ATTRACTOR_STEP_WORK`, against `work_limit()` (2**27 + 16384 per pixel). When a style gains a field or a loop, update its `validate` in the same change: `every_scene_number_is_range_checked` (`core/engine/tests/validation.rs`) sets each fixture number to 1e300, and `scenes_stay_well_within_the_work_limit` (`invariants.rs`) holds built-in scenes to an eighth of the limit at sizes up to 4K.
- **Portable fixtures (`core/engine/tests/fixtures/`):** one JSON file per style: a scene at 48×36, seed 3, phase 0.37 and a palette cycling through the built-ins, with the SHA-256 of the packed RGB a `portable` build renders. The committed scenes came from the Python builders before the cutover (from the Rust builder for `attractor`). `fixtures.rs` renders them (exact hashes with `portable`), builds each scene from scratch with `build_scene`, and requires one fixture per style. After a deliberate change, run the ignored `bless_fixtures` test on its own: it rewrites only a fixture that is missing, does not parse, holds a scene that no longer deserializes or validates, or whose Rust-built scene renders another hash (with sorted keys and `serde_json` number formatting), and leaves the rest byte for byte. Scenes load through serde (`scene_from_json`, feature `json`, with `serde_json`'s `float_roundtrip`, which must stay on). JSON is for generated files only; hand-edited data should use TOML or YAML.
- **Golden hashes (`core/cli/tests/golden/`):** `workloads.txt` (hand-edited) lists output names and the binary's arguments; a line holding `{style}` is expanded for every style in `--list-styles`. `SHA256SUMS` holds each output file's SHA-256 and `PIXELS` each decoded frame's (`name#frame`), both from a `portable` build. `golden.sh` (POSIX sh, also under Git Bash and in the Python-free container) requires the workload and manifest names to be the same set before comparing hashes; `golden_pixels.rs` decodes with the test decoders in `core/cli/tests/common/`, also requires the `fixture-<style>.png` frames to hash as the portable fixtures, and refuses to bless an incomplete directory. Re-blessing: an encoder-only change (a `flate2` or `miniz_oxide` update) re-blesses `SHA256SUMS` alone, after the pixel test passes against the unchanged `PIXELS`; a deliberate visual change re-blesses both, and the diff shows which workloads changed.
- **Binary (`core/cli`):** options with clap (`args_override_self`, so a repeated option takes its last value), the engine's palette table (`palettes.rs`), the checked `render`, its own PNG and APNG writer (`png.rs`, `flate2` at level 9 with filter None; `Apng::compress` compresses a frame on any thread and `Apng::frame` returns its chunks in order), its own GIF writer (`gif.rs`: 240 palette samples plus 16 greys shared by all frames, nearest entry cached per 5-bit colour cell, a variable-width LZW encoder whose width growth mirrors the decoder, delays in whole hundredths, at least 2), and an atomic write (`output.rs`: a temporary file created with mode 0o666, so the umask applies, then a rename; `atomic_write_with` lets frames go to disk as they finish). Animations render and encode whole frames as jobs on Rayon's pool (`in_order`), at most `frames_in_flight` at once (one per thread, within `FRAMES_IN_FLIGHT_BYTES`, 1 GiB by `frame_bytes`: `FRAME_BYTES_PER_PIXEL`, 32, and `FRAME_BYTES_PER_SIDE`, 320 per pixel of width + 2 × height, both sized for `lissajous`; raise them if a style needs more), written in frame order, so the first failing frame's error is reported. Limits (`check_limits`, before rendering): `MAX_FRAME_PIXELS` (100 M), `MAX_SIDE` (100,000, because some scenes grow with a side alone and are built before validation), `MAX_TOTAL_PIXELS` (2**32 pixels in all frames) and `MAX_FRAMES` (65,536); `--no-limits` skips them, but more than 2**31 APNG frames and GIF sides over 65,535 are refused as format limits. Exit status 2 for refused arguments and limits (`Failure::Usage`, including the `--slideshow` seed overflow), 1 for a failure while rendering or writing (`Failure::Runtime`).
- **Colors:** palette stops are sRGB, and the writers store samples unchanged. Do not introduce a linear-to-sRGB conversion. Every built-in palette has at least 5 stops and a dark first stop (every channel below 64), since many styles take their background from it; `palettes.rs` is sorted by name.

## Conventions

- **Size independence:** express shape sizes, radii, wave frequencies and noise scales relative to the canvas (`min(width, height)` or `max(width, height)`), not in pixels. Keep wave frequencies well below Nyquist (π radians per pixel). `invariants.rs` checks palette range, aliasing and canvas scaling.
- **Brightness:** prefer `1 - exp(-k * v)` tone mapping over dividing by a fixed count, which left several styles nearly black. Every style must span more than 0.5 of its palette at 64×64 (`every_style_uses_a_wide_palette_range`).
- **Changing a style's output:** there is no Python reference any more; styles live in Rust only. A deliberate change re-blesses the style's portable fixture (`bless_fixtures`) and both golden manifests in the same PR, and the PR shows a before-and-after render. An accidental change fails the fixture tests and the golden check.
- **Behavior-preserving refactors:** the golden check, the pixel test and the fixtures must pass unchanged.
- **Keep docs in sync:** when adding or renaming a style, update both macro lists, the README style table and, if relevant, the tests; it also needs a `validate`, a fixture and blessed golden hashes (its `{style}` workloads fail until then). A new built-in palette goes into `core/engine/src/palettes.rs` (sorted) and the README palette table.
- **Start from `origin/main`:** several sessions work on this repository in parallel, so run `git fetch` and `gh pr list` before starting and branch from `origin/main`; a local `main` can be several PRs behind.
- **New crate versions:** pin releases at least two weeks old (check the crates.io release date; pin in `Cargo.lock` with `cargo update -p <crate> --precise <version>` when a newer release is too fresh), and look up unfamiliar transitive crates before committing the lockfile.

## SonarQube and CodeQL triage notes

Project key: `juusolatva_abstract-art`.

- **Atomic-write mode (`core/cli/src/output.rs`, 0o666):** if a scanner flags the permissive mode, it is a false positive. 0o666 is the mode an ordinary file creation passes; the kernel removes the umask bits, so the file gets the permissions of any new file (0o644 under the usual umask 0o022), which `new_files_get_the_umask_default_mode` checks. A fixed stricter mode would override a user's umask, and reading the umask means changing it process-wide. Dismiss as a false positive.
- **rust:S6164 (approximate constant, e.g. `1.414` read as `SQRT_2`) in `ATTRACTOR_TABLE`:** false positive. The table entries are parameter values that must stay exactly as they are; a library constant would change the figure.
- **Re-raised findings:** moving or renaming code makes SonarQube report the same finding again at the new location. Triage it the same way, noting in the comment that the code moved.

### Rendering quirks (not bugs, but worth knowing)

- **Mandelbrot:** ignores the seed by design; only `--slideshow` gives identical frames.
- **Comet length:** comet length scales with the width only, so trails are short on tall canvases.
- **Cosmic arm:** the arm in `cosmic` is placed along a straight ray, so it is not really curved.
- **Pixel-based sizes:** some features are still measured in pixels: star dots in `orbits`, `nebula` and `constellations`; brush and ember widths in `ember` and `comet`; and pixel-scaled noise in `waves`, `orbits`, `interference`, `bloom`, `torus`, `pinwheel`, `galaxy` and `quasar`. Their detail changes with resolution.
- **Culling:** skips happen only where a contribution is exactly zero (row filtering of stars and glyphs, exact-zero ring bands in `mandala`, column bounds in `ember`, bounding-box pruning of segments in `circuit`), either from a hard cutoff or because `exp()` underflows past `GAUSSIAN_ZERO` standard deviations; any other skip would change the images.
