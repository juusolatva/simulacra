# AGENTS.md

Guidance for coding agents working in this repository. User-facing documentation lives in [README.md](README.md).

## Project overview

`simulacra.py` is a generative art tool (Simulacra, formerly Abstract Art) that draws abstract patterns and stylized representations of real phenomena: 48 styles, 24 palettes, PNG, APNG and GIF writers and a CLI. `test_simulacra.py` holds the `unittest` suite and `bench_simulacra.py` the benchmark. The pure-Python module needs only the standard library and stays usable on its own as the reference implementation. `core/` is a Cargo workspace: `engine` (the renderer, usable without Python), `py` (the optional `simulacra_core` extension, which renders all 48 styles natively for `simulacra.py`) and `cli` (the standalone `simulacra` binary, in preview for `blobs`, `mandelbrot` and `waves`, whose scene builders are ported to Rust). The Rust rewrite toward a Python-free application is tracked in `PLAN.md`: Phases 1, 2 and 2b are done, Phase 3 is in progress. Third-party dependencies are allowed; the standard-library-only rule has been dropped.

## CI

- **Tests (`.github/workflows/tests.yml`):** runs on every push to main and every pull request, forks included (no secrets): the suite on Python 3.12 and 3.14, each without and with the Rust core, plus Python 3.12 with a `portable` core (the two default-core jobs also build the standalone binary and run `StandaloneCliTests` against it); and `cargo test` plus Clippy with `-D warnings` on both backends, for the workspace and then for the engine alone (which also fails if `simulacra_engine` pulls in PyO3 without its `python` feature), plus the portable fixtures (`--features json,portable`).
- **Slow tests (`.github/workflows/slow-tests.yml`):** the slow checks (`SIMULACRA_SLOW=1`: native versus Python at larger sizes, and every attractor table entry) run only when started by hand (`workflow_dispatch`), because they take about 10 minutes on a runner; being a separate workflow, they are not listed on pull requests. Run the slow checks locally instead (see Commands) before opening a PR that changes a Rust shader, a scene builder or the attractor table, and say in the PR that they passed.
- **SonarQube Cloud (`.github/workflows/sonarqube.yml`, `sonar-project.properties`, `.coveragerc`):** runs the suite twice under `coverage` (once without the Rust core, once with it built via `maturin develop`, appended into one report) and scans with `coverage.xml`. Only Python coverage is collected; Rust is exercised through the same tests. `sonar.sources` lists the Python files and the three crates' `src` directories (add a new crate there), and the generated palette table `core/engine/src/palettes.rs` is excluded from duplicate detection (`sonar.cpd.exclusions`), since its rows of tuples made the duplication gate fail. The scan needs `SONAR_TOKEN` and skips pull requests from forks, which cannot read secrets. SonarQube's Automatic Analysis must be off, because it conflicts with CI analysis.
- **OSV-Scanner (`.github/workflows/osv-scanner.yml`):** scans `-r ./`, which finds `core/Cargo.lock` (the Python module has no dependencies). Pull requests and merge groups use the PR workflow, and pushes to main, a weekly schedule and manual runs use the full scan. Results are uploaded to GitHub code scanning, except for pull requests from forks, whose tokens cannot write security events, and for merge groups, whose scan compares the commit with itself (the PR workflow reads `GITHUB_BASE_REF`, which GitHub sets only for pull requests). Actions are pinned by commit SHA with the version in a comment.

## Architecture

- **Registry:** `STYLES` maps each style name to its `render_*` function. It drives `render()`, the CLI `--style` choices and the tests, and is the only place a style is registered.
- **Renderer contract:** `render_x(width, height, seed, palette_name, phase=0.0)` returns `height` rows of `width` `(r, g, b)` integer tuples (every built-in style takes `phase`; see Animation below). Map intensities through `palette_color(stops, t)` with `t` in `[0, 1]`.
- **Randomness:** use a local `random.Random(seed)`. Never touch the global `random` state; a test enforces this. Output must be deterministic for a given seed, size and palette. Scene builders may use only what the Rust port supports: `random.Random(seed)` with an integer seed, and `random()`, `uniform`, `randint`, single-argument `randrange`, `choice` and `getrandbits` (up to 128 bits). `simulacra_engine::PyRandom` (`core/engine/src/random.rs`) reproduces those draw for draw, so builders can move to Rust later; using another method (`shuffle`, `sample`, `gauss`, ...) means porting it first. `core/engine/tests/random_reference.json` holds CPython sequences that `tests/py_random.rs` replays; regenerate it with `make_random_reference.py` only if the call mix changes (CPython's output is platform-independent).
- **Noise:** `fbm()` returns values in `[0, 1]` centered near 0.5. Do **not** treat it as `[-1, 1]` (`n * 0.5 + 0.5` was a past bug in 8 styles). Use `_contrast(n, gain)` to stretch it, and `polar_noise()` for anything indexed by an angle, because raw `theta` creates a seam at ±π.
- **Colors:** palette stops are sRGB, and the writers store samples unchanged. Do not reintroduce a linear-to-sRGB conversion.
- **Writers:** `_atomic_write()` writes to a temporary file created with `os.open(..., 0o666)` and then calls `os.replace()`. Never call `os.umask()`, since it is process-wide and unsafe with threads.
- **Rust core (`core/`, module `simulacra_core`):** optional; imported as `_core` (None when missing). `core/` is a Cargo workspace: `core/engine` (package `simulacra_engine`) holds the math, noise, palettes, scene structs and shaders and has no PyO3 unless its `python` feature is on; `core/py` (package `simulacra_core`, built with `maturin develop -m core/py/Cargo.toml`) is the Python adapter. Python generates the scene (all `random.Random` use) with a `_x_scene()` builder that returns plain data. `NATIVE_STYLES` maps each native style to its builder, and `_core.render(style, width, height, seed, stops, scene)` reads the scene into a per-style Rust struct (`#[cfg_attr(feature = "python", derive(pyo3::FromPyObject), pyo3(from_item_all))]`; never an unconditional PyO3 derive or import in the engine), shades rows in parallel (rayon) and returns packed RGB bytes. `render()` and `render_rgb()` use it automatically. Pass seeds through `_seed32()`. The engine's `for_each_style!` macro in `core/engine/src/lib.rs` is the one Rust list of styles: it generates `STYLES` and the adapter's dispatch, so a ported style needs one line there. `_core.STYLES` must match `NATIVE_STYLES` (tested). `core/cli` (package `simulacra_cli`, binary `simulacra`) is the standalone tool: it uses the engine's ported scene builders (`build_scene`, `SCENE_BUILDERS` in `core/engine/src/scenes.rs`; a builder is an associated `build` on the scene struct, a port of the Python `_x_scene()` that must match it draw for draw), the engine's palette table (`palettes.rs`, kept equal to `PALETTES` by a test through `_core.palettes()`; change both together), the checked `simulacra_engine::render`, its own PNG writer and an atomic write with mode 0o666 (`core/cli/src/output.rs`). Its options and messages follow `simulacra.py`; `StandaloneCliTests` compares them when `SIMULACRA_CLI` is set. Scene structs also derive `serde::Deserialize` under the engine's `serde` feature (`#[cfg_attr(feature = "serde", derive(serde::Deserialize))]` on the line after the PyO3 one); `deserialize_scene(style, deserializer)` reads any serde format and `scene_from_json` (feature `json`) reads JSON with `serde_json`'s `float_roundtrip`, which must stay on (a unit test fails without it).
- **Portable fixtures (`core/engine/tests/fixtures/`):** one JSON file per native style: a scene from the Python builder at 48×36, seed 3, phase 0.37, with the SHA-256 of the packed RGB a `portable` core renders. `cargo test -p simulacra_engine --features json,portable` renders them without Python and compares hashes on every platform; the scenes are committed rather than rebuilt because Python's scene data depends on the platform libm. When a shader or scene builder changes output on purpose, regenerate them with `core/engine/tests/make_fixtures.py` (it refuses a non-portable core) and review the diff; a new native style needs a fixture (`every_style_has_exactly_one_fixture`). JSON is for these generated files only; hand-edited data should use TOML or YAML.
- **Native output must be byte-identical to Python.** Port expressions operation-for-operation in the same order (no algebraic rewrites, no `mul_add` outside the error-free products in `py_hypot`, no `clamp` where Python's `max/min` NaN behavior differs), and keep the Python renderer as the reference. `test_native_styles_match_python_exactly` enforces this; extend its cases when porting a style. Move the style's random layout into `_x_scene()` first and have the Python renderer use it, verifying unchanged output with a fingerprint. Call libm functions through the `Libm` trait in `core/engine/src/math.rs` (`x.m_exp()`, `m_sin`, `m_cos`, `m_tan`, `m_atan`, `m_atan2`, `m_powf`, `m_ln_1p`), never the `f64` methods (`core/clippy.toml` forbids them outside `math.rs`): the default build uses the platform libm like Python, and the `portable` feature (`--features portable`) swaps in the pure-Rust `libm` crate (see `PLAN.md`, "Measured `portable` drift"). Python's `math.hypot` is CPython's own algorithm, not libm, so Rust calls `math::py_hypot(x, y)`, an exact port that both backends share; `f64::hypot` is forbidden as well. Standalone release binaries will use `portable`; keep development builds on the default so native output stays byte-identical to Python. A core built with `portable` reports `_core.PORTABLE`, and the tests then hold only `PORTABLE_DRIFT_STYLES` (`attractor`, `cymatics`) to measured bounds instead of exact equality (`_assert_native_close`); CI runs the suite against such a build. Rust helpers that replicate Python semantics live in `core/engine/src/geometry.rs` (`py_mod`, `py_sum`, polygon and segment distances) and `core/engine/src/styles/mod.rs` (`gaussian`, `unit`, `center`, `small_side`).
- **Animation (`phase`):** a style moves by adding `_loop(phase, k)` (`tau * k * phase`, `k` a whole number, negative to reverse) to phases and angles in its `_x_scene()`, so the Rust shader needs no change and native stays byte-identical. Keep it free of new random draws (derive per-item values from the index) so scenes at phase 0 match the still image, and give each style an entry in `ANIMATED_STYLES` and `_animated_scene()` in `NATIVE_STYLES`. Offsets that are not whole turns, such as the drift in `voronoi`, are measured from their starting value so phase 0 adds exactly 0.0.
- **Looping noise:** `fbm(..., phase=)` (Rust `fbm_loop`) blends a stack of ordinary 2D noise layers, each the same noise under the seed plus `7919 * layer`. Layer 0 is the real seed, so phase 0 is exactly the still noise, and the layer index wraps, so phase 1 repeats phase 0. Octave `i` steps through `_NOISE_LAYERS + i` layers per loop so the octaves do not all stall or pulse together. The blend is linear on purpose; with an eased blend the speed varied about 3x and hitched at the loop point. A style animates its noise by passing `phase` to `fbm` and putting `"phase"` in its scene for the shader. Circling objects use `_circle_offset()`, whose offset is exactly zero at phase 0.
- **Brush and trail styles** animate by moving their scene data: positions circle with `_circle_offset()` (comet, ember, flowfield starts, ink control points, constellation stars via `_drift_stars()`), and lissajous turns its curve phases. Constellation pairs are chosen from the starting positions so the line set stays constant.
- **Rotation and sweeps:** `torus` rotates its model points with `_turned()` (an exact identity at angle 0) and takes the depth range from the turned knot but the centre and scale from the unturned one; `quasar` adds `_loop()` to the jet's spin angle; `mandala` adds alternating loops to ring and spoke phases; `orbits` and `cosmic` use `_circle_offset()` / `_drift_stars()`. Noise seeded per ring (quasar, mandala) stays fixed because the Rust core owns that noise.
- **Mandelbrot zoom:** `_mandelbrot_scene()` gives the Rust shader `scale`, `center` and `iterations`. The zoom factor is `exp(-depth * ease)` with a cosine ease, so it dives and returns; the centre moves with `1 - closing` so the target stays on screen, and phase 0 is exactly the old view (`closing` is exactly 1.0). Shards use `_turned_about()`, which adds the rotation offset to the point (rebuilding it from the centre would not be exact at angle 0).
- **Marbling and attractor:** `marbling` undoes its ops (drops and combs, each exactly invertible) from last to first per pixel, so scene order is the order they were applied; drops circle with `_circle_offset()` and comb strength is scaled by `cos(_loop())`. `attractor` counts integer hits, so sequential order does not matter, but byte-identity relies on Rust and Python using the same libm `sin` and `cos` along a chaotic orbit. Its parameters come from `_ATTRACTOR_TABLE` (256 sets, mirrored on one random bit) rather than a search, so the choice uses only integer draws and no libm can change it. Entries were checked offline at 384 phases for a lively figure that stays the same from four nearby start points under both glibc and the `libm` crate (no bistable figures or collapses into periodic cycles; see "Attractor parameter table" in `PLAN.md`). The tests recheck a sample with `_assert_attractor_entries_meet_the_table_criteria()`, and every entry at 48 phases when `SIMULACRA_SLOW` is set. Add entries only with the same offline checks.
- **Space styles:** distances use `sqrt(dx * dx + dy * dy)` on both sides rather than `hypot`, so Python and Rust agree to the last bit. `lunar` marches a soft shadow through its analytic crater height field (pixels facing away from the sun skip it); `asteroids` shades rocks nearest first and takes the first hit; `blackhole` maps the sky through `1 - 1.6 / r**2` to fake lensing; `supernova` evolves its filaments with looping `fbm`.
- **Animation is complete:** all 48 styles are in `ANIMATED_STYLES`. The slideshow path in `_frame_plan` remains for a future style without motion and for `--slideshow`.
- **Woodblock:** `_woodblock_scene()` samples animated hill, cliff and wave silhouettes per column in canvas-relative units. Python and Rust shade the same overlapping layers and carved contour grooves; the final palette stop is paper. `watercolor` is a palette, not a blur or texture filter.
- **Per-tile styles (`mosaic`):** `_mosaic_scene()` computes one palette position per tile on a grid about `_MOSAIC_TILES` tiles across the short side, so the work does not grow with the canvas, and the Rust shader (`core/engine/src/styles/mosaic.rs`) only expands tiles and grout to pixels. Noise there is sampled in tile units, and `value_noise` has an 8-unit cell, so tile-space noise needs scales near 1 rather than the 0.01 used per pixel. Patterns move by whole tiles (`_mosaic_shift`), wrapping after one period per loop.
- **GIF (`write_gif`):** the table is 240 palette samples plus 16 greys, shared by all frames; pixels map to the nearest entry once per 5-bit colour cell (cached across frames), and `_lzw_codes()` is a variable-width LZW encoder whose width growth mirrors the decoder, which lags one entry behind. Delays are whole hundredths of a second (`_gif_delay`). Tests decode the output with a reference decoder in `test_simulacra.py`.
- **Packed frames:** `render_rgb()` returns `width * height * 3` bytes; the writers accept rows or packed bytes (`_packed_rgb`). The CLI uses packed frames.
- **Helpers for keeping functions small:** `_shade(width, height, stops, value)` builds rows from a per-pixel `value(x, y)`. `_sample_by_length()` and `_segment_box()` sample curves and yield the pixels near a segment. `_RowFilter` hands per-pixel code only the objects that can reach a row. `_glow_pixels()` maps a flat intensity buffer to rows.

## Conventions

- **Size independence:** express shape sizes, radii, wave frequencies and noise scales relative to the canvas (`min(width, height)` or `max(width, height)`), not in pixels. Keep wave frequencies well below Nyquist (π radians per pixel). The tests check palette range, aliasing and canvas scaling.
- **Brightness:** prefer `1 - exp(-k * v)` tone mapping over dividing by a fixed count, which left several styles nearly black. Every style must span more than 0.5 of its palette at 64×64 (`test_every_style_uses_a_wide_palette_range`).
- **Cognitive complexity ≤ 15 per function** (SonarQube S3776). Move per-pixel or per-sample bodies into module-level helpers placed directly above the style that uses them, and use comprehensions or `_shade()` for the row loops.
- **Behavior-preserving refactors:** fingerprint every style's output before and after (hash `render()` at a few sizes, seeds and palettes) and require identical hashes. When a change is meant to alter visuals, render a contact sheet of all styles and inspect it.
- **Naming:** local names and parameters use `snake_case` (S117); no single uppercase names such as `R`.
- **Keep docs in sync:** when adding or renaming a style, update `STYLES`, the module docstring's style list, the README style table and, if relevant, the tests. A new native style also needs a `portable` fixture (`make_fixtures.py`) and a line in `for_each_style!`. A new built-in palette goes into both `PALETTES` and `core/engine/src/palettes.rs` (`test_native_palettes_match_python`). A change to a scene builder that is ported to Rust (`SCENE_BUILDERS`: `blobs`, `mandelbrot`, `waves`) needs the matching Rust change in the same PR (PLAN.md's ownership rule); `StandaloneCliTests` and `ported_scene_builders_render_the_fixture_hash` catch a mismatch.
- **New crate versions:** pin releases at least two weeks old (check the crates.io release date; pin in `Cargo.lock` with `cargo update -p <crate> --precise <version>` when a newer release is too fresh), and look up unfamiliar transitive crates before committing the lockfile.

- **pythonsecurity:S8705 (command argument injection in the benchmark's `run_cli`):** false positive. The command is a list without a shell, built from the constant `CLI_WORKLOADS`, an integer seed and a path in our own temporary directory.
- **S1172 (`seed` unused in `render_mandelbrot`):** accepted, because the shared renderer signature requires it. Other S1172 findings are real: a helper that nothing calls any more (for example `_no_scene` after mandelbrot got a scene) should be deleted.
- **S9073 (composite assertion):** split `assert a and b` into two asserts, including in test helpers.
- **Start from `origin/main`:** several sessions work on this repository in parallel, so run `git fetch` and `gh pr list` before starting and branch from `origin/main`; a local `main` can be several PRs behind.
- **Workflow with PRs:** SonarQube Cloud (CI analysis) runs on every PR. The other review tools (bots and GitHub apps) change over time, so check which ones reported on the PR rather than expecting a fixed set. Fix valid findings and answer each one, naming the commit or explaining why nothing changed: on its review thread, or in a PR comment for a tool that posts all its findings in one comment. ## Known issues and follow-ups

Open ideas, none started: port more scene builders so the standalone binary covers more styles (PLAN.md Phase 4; it has `blobs`, `mandelbrot` and `waves`, still images only, and no animation or GIF output until Phase 5); validate scenes in the engine before reading them from untrusted sources (indices, lengths against the canvas and palette, loop limits; see PLAN.md Phase 3; until then `deserialize_scene` and the adapter treat scenes as trusted); stream animation frames to the writers instead of holding them all in memory (PLAN.md Phase 5); collect Rust coverage (PLAN.md Phase 6); animate the per-ring turbulence in `quasar` and `mandala`, which needs the Rust noise to take a phase.

### Performance

Pure Python took about 178 s for the original 36 styles at 640×480 (see `bench_simulacra.py`). The Rust core now covers every style in `NATIVE_STYLES`. Algorithmic fixes were done in Python first because they carry over to Rust. Single-run timings on this machine vary by about ±30%, so use `--repeat` and compare against a fresh baseline.

- **Culling has been done** for the cases that keep output byte-identical: row filtering (`_RowFilter`) for stars in `orbits`, `nebula`, `cosmic` and `constellations`, and for glyphs in `mandala`; exact-zero ring bands in `mandala`; column bounds in `ember`; and bounding-box pruning of segments in `circuit` (`_nearest_segment`). A skip is allowed only where a contribution is exactly zero, either from a hard cutoff or because `exp()` underflows past `GAUSSIAN_ZERO` standard deviations.
- **`render_torus` and `render_lissajous`** now sample their curves at a spacing tied to the glow width and measure distances to line segments (`_sample_by_length`, `_segment_box`), so curve drawing grows with the pixel count. This fixed the torus issue Greptile raised on PR #1. Their remaining cost is per-pixel work (background noise in torus).
- **Brush, trail and curve styles** (torus, lissajous, constellations, ink, flowfield, comet, ember) accumulate in a fixed order, and float addition order changes results. Rust stamps sequentially in exactly Python's order into a shared buffer and then shades in parallel (`core/engine/src/styles/brush.rs`). Python still samples the torus and lissajous curves and picks the constellation pairs in the scene builder; Rust does the per-pixel and per-stamp work. Parallelizing the stamping (for example one band of rows per thread, each replaying all stamps in order) is possible if `ink` at very large sizes matters.
- **Scene builders:** a native style needs a `_x_scene()` returning plain data (numbers, tuples, lists). A scene must reproduce the exact random draws, including any that depend on the palette: `orbits` takes the stop count because `randrange(n_stops)` consumes a number of random bits that depends on `n_stops`.
- **Python numeric semantics in ports:** `x ** n` with a float base is libm `pow`, so use `powf` (not `powi`, which multiplies repeatedly and can differ in the last bit). `round()` is half-to-even (`round_ties_even`), `int()` truncates (`as i64`, fine for non-negative values), and sorting `(distance, value)` tuples breaks distance ties by value (see `Voronoi`).
- **Python `sum()` is compensated since 3.12.** Rust must use `geometry::py_sum` wherever Python sums floats with `sum()` (currently `render_geo`), and `geometry::py_mod` for Python's float `%`.
- **PNG encoding:** `_packed_rgb` has a fast `bytes()` path for in-range integer channels (about 0.03 s at 640×480), and `zlib` level 9 compression dominates the encoding time at 4K.
- **Resource guards:** the CLI enforces `MAX_FRAME_PIXELS` (100 M) and `MAX_ANIMATION_BYTES` (1 GiB of packed frames) through `check_limits()`; `--no-limits` skips them and the Python API does not enforce them. The CLI still holds all animation frames in memory; streaming them to the writer would need `write_animated_png` to accept an iterator with a known count.

### Rendering quirks (not bugs, but worth knowing)

- **Mandelbrot:** `mandelbrot` ignores the seed by design; its animation is a zoom that does not depend on the seed, and only `--slideshow` gives identical frames.
- **Animation:** styles in `ANIMATED_STYLES` move with `phase` (currently every style); a style outside it is a slideshow of consecutive seeds under `--frames` (the CLI prints a note). `phase` 0 must give exactly the still image the style produced before it moved, so check that with fingerprints when adding a style.
- **Comet length:** `render_comet` scales comet length by `width` only, so trails are short on tall canvases.
- **Cosmic arm:** the arm in `render_cosmic` is placed along a straight ray (`dist_along` formula), so despite the docstring it is not really curved.
- **Pixel-based sizes:** some features are still measured in pixels: star dots in `orbits`, `nebula` and `constellations`; brush and ember widths in `ember` and `comet`; and pixel-scaled noise in `waves`, `orbits`, `interference`, `bloom`, `torus`, `pinwheel`, `galaxy` and `quasar`. Their detail changes with resolution.
- **Noise octaves:** `fbm()` uses the same seed for every octave, so the octaves are correlated at the lattice points. Changing this would alter every noise-based style.
